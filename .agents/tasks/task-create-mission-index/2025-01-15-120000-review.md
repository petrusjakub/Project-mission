# Single-page product landing for MiSSION insurance

A self-contained HTML page presenting Manulife's MiSSION (MiSmart Insurance Solution) unit-link life insurance product. The page is a marketing/sales tool aimed at Indonesian lay consumers, built as a single file with inline CSS and JS, following a pre-existing template (`index (17).html` for a different Manulife product). It includes a sticky WhatsApp banner, tabbed navigation across seven content sections, an interactive illustration calculator, an FAQ accordion, and a floating WhatsApp button — all wired to one agent's phone number.

Watch for: the illustration calculator uses a naive linear COI model that diverges significantly from actuarial reality at higher ages and lower premiums, which may produce misleading projections (**confirmed**); the calculator's UP formula caps every premium tier at Rp100M, contradicting the example section showing UP = Rp1B (**confirmed**); the `table` element is styled with `display:block` which breaks semantic table accessibility (**confirmed**).

## High-level view

The page replicates the CSS/JS skeleton of the MiUHC template — same WA banner, tab system, card/grid/accordion patterns — swapping only the product content. The template's limitations (accessibility, table rendering) carry over unchanged.

The illustration calculator projects policy values over 25 years using a fixed 5% net return and a linear cost-of-insurance approximation (`(age + year) * 500 * (UP / 100M)`). The linear formula underestimates COI at older ages (actuarial mortality curves are exponential), overstating policy values for higher entry ages or longer horizons. Additionally, the UP formula `Math.max(premi * 5, 100000000)` maps every available premium tier to a flat Rp100M — contradicting the "Contoh Ilustrasi Lengkap" section which quotes UP = Rp1B for Rp16M/year premium. A consumer toggling between the calculator and the example section will see inconsistent numbers.

The only external interaction is the WhatsApp deep link. The hardcoded agent identity (name + phone in four places) means the file cannot be reused without manual find-and-replace.

The tab and FAQ components rely on JS class manipulation rather than native `<details>`/`<summary>` — no `<noscript>` fallback exists, so with JS disabled only the first tab is visible and the calculator is empty.

<summary>Issues (6)</summary>

1. **Linear COI model diverges at higher ages** — The calculator uses `(age + year) * 500 * (UP / 100M)` which is linear; real mortality tables are exponential. For entry age 45+ the projected policy values will be significantly overstated. Replace with an exponential approximation or add a stronger caveat that suppresses output for high-age/low-premium combinations.
2. **UP formula contradicts example section** — `Math.max(premi * 5, 100000000)` yields Rp100M for every tier in the dropdown (since even 16M * 5 = 80M < 100M). The "Contoh Ilustrasi Lengkap" section shows UP = Rp1B for the same Rp16M premium. Either the formula needs to reflect real underwriting (UP as an input, not derived) or the example text needs to match the calculator output.
3. **Unused `akuisisi` array in calculator** — A 25-element array is declared but never referenced; the code uses a separate `akuisiRate` variable. Remove the dead declaration.
4. **`display:block` on `<table>` breaks accessibility** — Screen readers and some mobile browsers lose table semantics when `display:block` is applied. Wrap tables in an overflow container instead, or use `display:table` with an outer `overflow-x:auto` div.
5. **Hardcoded agent identity prevents reuse** — The agent name, phone number, and WhatsApp link appear in four separate places with no templating mechanism. Any future agent reuse requires a manual find-and-replace across the file.
6. **No `<noscript>` fallback for calculator or tabs** — If JavaScript is disabled, all tab content except the first is hidden and the calculator produces no output. A `<noscript>` block advising the user, or showing all tabs expanded, would improve graceful degradation.

## Calculator projection model

The `updateIlustrasi()` function loops year-by-year accumulating `nilaiPolis`:

```javascript
var coiEstimate = (usia + y) * 500 * (up / 100000000);
nilaiPolis -= coiEstimate;
nilaiPolis *= (1 + netReturn);
```

The COI formula grows linearly with attained age, but actual mortality cost tables grow roughly exponentially after age 40. For an entry age of 30, the underestimate is modest through year 15 but becomes material by year 20-25. For entry age 45, even the year-10 projection is likely over-optimistic.

An `akuisisi` array of 25 elements is declared (`var akuisisi = [0.30, 0.30, 0.30, 0, ...]`) but never read — the code uses a locally computed `akuisiRate`. Dead code.

The UP calculation `Math.max(premi * 5, 100000000)` evaluates to Rp100M for every premium in the dropdown:

- Rp4M * 5 = Rp20M → capped at Rp100M
- Rp8M * 5 = Rp40M → capped at Rp100M
- Rp12M * 5 = Rp60M → capped at Rp100M
- Rp16M * 5 = Rp80M → capped at Rp100M

Yet the static "Contoh Ilustrasi Lengkap" block below the calculator states UP = Rp1.000.000.000 for the Rp16M premium. A consumer switching between the interactive table and the static example will see the UP column change from Rp100M to Rp1B, with no explanation. The fix is either making UP a user-selectable input in the calculator or aligning the static example to match the formula's output.

## Table rendering and accessibility

The global CSS rule `table{...display:block}` strips table semantics from the accessibility tree. A screen reader navigating these tables won't announce row/column relationships. The fix is wrapping each `<table>` in a `<div style="overflow-x:auto">` and removing `display:block` from the table itself.

The tab `<li>` elements carry `role="tab"` but the content panels have `role="tabpanel"` without `aria-labelledby` linkage. The `tabs-container` also lacks `role="tablist"`. Minor ARIA gaps inherited from the template.

## No-JS degradation

With JavaScript disabled: only the "Ringkasan Produk" tab is visible (it carries `class="active"`), all other tabs are `display:none`. The FAQ answers are permanently collapsed. The illustration section renders an empty div. A `<noscript>` block with a CSS override showing all tabs expanded would be a low-effort fix.
