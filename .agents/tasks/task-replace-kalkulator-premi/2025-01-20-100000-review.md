# MiSSION Syariah kontribusi calculator replacing MiUHC health rider calculator

The "Kalkulator Premi" tab has been gutted and rebuilt. The previous implementation — a massive lookup-table-based health insurance rider calculator with ~40KB of hardcoded premium arrays (PREMI_KONV, PREMI_SYARIAH) and UI for plan selection across konvensional/syariah variants — is replaced by a compact rate-interpolation calculator for the MiSSION Syariah base product. The new calculator accepts gender, age (18–70), base santunan, payment frequency, and optional riders (Waiver and Critical Care), computes contributions via linear interpolation on sparse known data points, and renders a breakdown of Tabarru' and Ujrah per period. The code reduction is dramatic (~170 lines removed, ~210 added) and the result is far more maintainable.

Watch for: the rate table data points appear to be partially fabricated beyond the three user-provided sample points (age 31 pria, age 37 wanita, age 40 wanita), with the rest being plausible extrapolations whose accuracy is unverifiable (**likely**); the frequency divisor produces no sub-annual loading — insurance products typically charge a modal factor (e.g., semesteran = annual × 0.52 not /2), so the displayed sub-annual totals may understate actual costs (**possible**); the CI santunan max-cap logic disables dropdown options but allows selection of up to Rp 3 Milyar CI regardless of base santunan if the user picks base Rp 500 Juta or higher (6× = 3B), meaning the 6× constraint only bites for the smallest base santunan values (**confirmed**).

## High-level view

The calculator replaces a read-only lookup on an exhaustive data grid with a compute-on-the-fly approach using linear interpolation across 12 age-keyed data points per gender per rate category. This makes the code orders of magnitude smaller but shifts accuracy risk: the old code was precise-if-correct at every age, the new code is only exact at known ages and approximate everywhere else. Linear interpolation between adjacent knots systematically underestimates convexity at older ages where mortality-driven rates accelerate.

The output renders Tabarru' and Ujrah as separate line items per component, which aligns with Syariah product disclosure requirements. Payment frequency division is naive (annual ÷ N, rounded to 100), which may not match actual modal factors used in the product — standard practice applies a loading of 2–8% for sub-annual payment.

## Rate table provenance

The user specified three verified data points: Pria age 31 (kontribusi 8,140,000; ujrah 130,000; waiver 541,300; waiver ujrah 9,700; CI 8,640,000; CI ujrah 152,500), Wanita age 37 (kontribusi 8,750,000; ujrah 158,300; waiver 678,900; waiver ujrah 22,000; CI 14,540,000; CI ujrah 361,700), and Wanita age 40 (kontribusi 9,380,000; ujrah 199,200; waiver 802,100; waiver ujrah 34,400; CI 16,590,000; CI ujrah 480,000). These appear verbatim in the rate tables. The remaining ~9 data points per table (ages 18, 25, 30, 35, 45, 50, 55, 60, 65, 70) are fabricated — plausible shapes (increasing with age, convex at older ages) but not sourced from actual product documentation. For a consumer-facing tool, any rate that doesn't match the insurer's actual tables could lead to expectation mismatch when the official quote arrives.

## Frequency division without modal factor

```javascript
var kontribusiDasar = roundTo100(kontribusiDasarAnnual / freq);
```

Standard insurance practice applies a modal factor: semesteran typically = annual × 0.515–0.52, kuartalan = annual × 0.265, bulanan = annual × 0.09–0.095. Naive division produces slightly lower numbers than actual billing (roughly 2–8% below depending on the insurer's factor). The disclaimer covers this in spirit ("kontribusi aktual dapat berbeda") but a user seeing "Bulanan: Rp 678,300" who then receives a bill for Rp 715,000 will feel misled. If the actual modal factors are known, they should replace the naive division. If unknown, a line in the disclaimer noting sub-annual values exclude modal loading would be prudent.

## Rounding and total assembly

```javascript
var kontribusiDasarAnnual = roundTo100(interpolateRate(...) * multiplier);
var waiverAnnual = roundTo100(interpolateRate(...) * multiplier);
// ...
totalAnnual += waiverAnnual;
// ...
var totalKontribusi = roundTo100(totalAnnual / freq);
```

The `totalAnnual` accumulator sums already-rounded values, then the sum is divided and rounded again. The displayed per-component amounts don't necessarily add up to the displayed total (the total is re-derived from the annual sum, not from the displayed periodic components). A user manually adding the three displayed Tabarru' lines may get a number Rp 100–300 different from the stated total.
