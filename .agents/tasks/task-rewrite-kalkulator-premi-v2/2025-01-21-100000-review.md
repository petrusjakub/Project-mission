# Kalkulator Premi rewrite with dual-currency rate engine and MiPOS-verified data

The Kalkulator Premi tab has been rebuilt from scratch: the old linear-interpolation calculator with fabricated multi-point rate tables is replaced by a two-point exponential interpolation engine using verified MiPOS data. The new implementation supports IDR and USD currencies, free-text santunan input, Top Up Berkala, Masa Pembayaran Kontribusi display, and rider checkboxes with configurable CI santunan. Rate tables contain only verified data points (2 per gender per rate category) with exponential interpolation filling the gaps. All 8 user-provided MiPOS scenarios produce correct annual totals. Frequency-divided amounts match within ±100 IDR or ±1-2 USD of MiPOS values.

Watch for: frequency-division rounding uses `Math.round` but MiPOS appears to use an inconsistent rounding method, causing ±100 IDR / ±1 USD discrepancies on 6 of 32 sub-annual test values (**confirmed**); Masa Asuransi Tambahan options always show 60/70/80/90 when waiver is checked, but MiPOS hides "60" for ages 59+ (**confirmed**); exponential extrapolation beyond the two known data points (ages 18-30, 46-70) is unverifiable and could be significantly wrong for extreme ages (**likely**).

## High-level view

The rate engine stores only four verified anchor ages from MiPOS (pria 31/45, wanita 37/59) per rate category and uses exponential interpolation to compute values at any age. This eliminates the fabricated data problem from the previous implementation at the cost of accuracy at ages far from the known points.

The rounding strategy — `Math.round(val/100)*100` for IDR, `Math.round(val)` for USD — matches MiPOS for all annual values and most frequency-divided values. A small number of half-value edge cases round in the opposite direction from MiPOS. No single rounding method (round, floor, truncate, banker's) reproduces all MiPOS outputs simultaneously, suggesting MiPOS uses higher internal precision that cannot be replicated from the observable data.

The UI is complete but the Masa Asuransi Tambahan dropdown needs age-based filtering, and Top Up Berkala minimum validation is absent.

## Rounding behavior at frequency boundaries

Six of 32 frequency-divided values across all test scenarios differ from MiPOS by exactly one rounding unit:

```
Pria 31  IDR  Waiver Kuar: 279,000 vs 278,900 (1115900/4=278975)
Pria 45  IDR  CI Bul:      2,052,500 vs 2,052,400 (24630000/12=2052500 exact!)
Pria 45  IDR  Waiver Kuar: 1,360,600 vs 1,360,500 (5442400/4=1360600 exact!)
Pria 45  USD  CI Kuar:     16 vs 15 (62/4=15.5)
Pria 45  USD  Waiver Sem:  65 vs 64 (129/2=64.5)
Wanita 37 USD Waiver Sem:  21 vs 20 (41/2=20.5)
```

The second and third IDR cases are already exact multiples of 100 — yet MiPOS shows 100 less. No rounding method can explain this from the given annual values. This points to MiPOS carrying different internal precision in its rate tables (perhaps more decimal places before the final round-to-100 step). The USD half-value cases all round down in MiPOS, suggesting `Math.floor` for USD frequency division — but this would break Wanita 37 KD kuartalan (350/4=87.5 where MiPOS gives 88, matching `Math.round`). No consistent rounding rule explains all MiPOS values simultaneously.

## Exponential extrapolation risk at extreme ages

```javascript
return rate1 * Math.pow(rate2 / rate1, (age - age1) / (age2 - age1));
```

For pria with anchors at 31 and 45 (14-year span), the growth factor is `(14830000/8140000)^(1/14) ≈ 1.0435` per year. Projecting backwards to age 18 gives ~4.66M; forward to age 70 gives ~43.3M. Actual insurance rate curves typically have different growth rates at the extremes — lower for young ages, steeper acceleration for older ages. Without bound-checking or additional data points, the extrapolated values for ages 18-30 and 46-70 could be materially wrong. The calculator accepts ages 18-70 but only has verified data for 31-59 (depending on gender).

## Masa Asuransi Tambahan age filtering

```javascript
if (waiverChecked) {
    var opts = [60, 70, 80, 90];
    for (var i = 0; i < opts.length; i++) { ... }
}
```

User data confirms that for age 59, only 70/80/90 appear. For ages 31, 37, 45 all four options (60/70/80/90) appear. The likely filtering rule is `opts[i] > age`, which correctly excludes 60 for age 59 (since 60 > 59 is true... wait, that would include it). More likely the rule is `opts[i] > age + 1` or simply that the minimum rider term must be at least 2 years beyond current age. The safest fix without more data: filter to `opts[i] >= age + 2`.

## Top Up Berkala validation gap

The calculation function displays the top-up as a separate line item (matching MiPOS behavior — top-up is informational, not added to the contribution total). But the minimum validation is absent: a user can enter any value below the threshold and the calculator won't warn. The minimums per frequency are IDR 1M/500K/250K/100K and USD 100/50/25/10 for tahunan/semesteran/kuartalan/bulanan respectively.
